## N. 差异报告（2026-08-12 实测）

### N1. 已修复的差异项
- **Qt Widgets 协议页缺"帧布局预览"**：原实现只有协议表格和字段编辑，无原型要求的"帧字节布局条状图 + 图例"。已通过 `setupProtoLayoutPreview()` / `renderProtoLayoutPreview()` 动态加入条状分段 + 图例，配色与 Web/原型一致，随字段增删改实时刷新。**尝试手段**：先在 `.ui` 中加控件，为避免破坏 65KB 复杂布局结构，改为在构造函数中程序化创建并插入 `protoEditLayout` 底部。**效果**：达成。
- **Web "后台运行"只是注释声称**：原 `runWeb` 直接前台 `app.exec()` 阻塞。已改为有图形环境显式 `--ui=web` 时用 `QProcess::startDetached` 派生子进程真正脱离终端后台服务，父进程退出，并以环境变量 `SERIAL_DEBUG_WEB_BG` 防止无限递归 detach。**效果**：达成，实测 8097 端口后台监听正常。

### N2. 仍存在的差异项（含根因）
| 项 | 原型要求 | 实际 | 尝试手段 | 根因 |
|---|---|---|---|---|
| QML 宿主编译进二进制 | `--ui=qml` 可用 | 未编译进（`--ui=qml` 提示"QML 未编译"） | 检查 `find_package(Qt6 Quick Qml)`；核实系统包 | 环境缺少 `libqt6quick*`/`libqt6qml*` 开发包，`HAVE_QML` 未定义。QML 四页源码完整存在，仅无法在当前沙箱编译 |
| Qt Widgets 字段"上移/下移" | 原型字段可调序 | 有"删除/新增"，上下移依赖表格选中后手工操作 | 核查 `.ui` 与槽函数 | 原型未在 mock 中绘制独立上下移按钮，21-224 项中的 70 项按"表格行可重排"实现，未做独立按钮（避免过度设计） |
| 校验和/校验字段（137） | G2 协议引擎含校验 | 核心字段解析完整，校验和字段未单独实现 | 查看 `ProtocolEngine.cpp` | 原型 mock 未定义校验和字段，核心引擎聚焦字段/字节序/比例/padding 解析 |

### N3. 约束与说明
1. **QML**：代码完整但当前 Linux 沙箱无 Qt Quick 开发包，无法编译进二进制。在有 Qt Quick 的机器上，`cmake` 会自动检测并启用 `HAVE_QML`。
2. **后台运行设计**：`--ui=web` 在有图形环境时自动派生子进程后台服务并打开浏览器；无图形环境（无头）时保持前台运行（无浏览器可开）。
3. 所有实现均通过 `cmake --build`（100%）与 `ctest`（8/8）验证。

### N4. Web 服务并发崩溃修复（2026-08-12 追加）
- [x] 230. **崩溃现象**：Web 服务在连续/并发访问时崩溃退出（`malloc(): unsorted double linked list corrupted`，SIGSEGV/134），导致用户访问时"服务不可用"或 IDE 静态浏览接管端口显示目录列表。
- [x] 231. **根因**：`run_web.cpp` 的 `readyRead` 处理中，`g_web_buf[s]`（`QHash<QTcpSocket*, QByteArray>`）返回的 `QByteArray&` 引用被跨多语句持有。并发连接插入新键触发 QHash 重新哈希时，该引用失效变成悬垂指针，后续 `buf += chunk` 写入已释放内存 → 堆损坏。
- [x] 232. **修复手段（已生效）**：改 `QByteArray &buf = g_web_buf[s]` 为按值 `QByteArray buf = g_web_buf.value(s)`，追加后按需 `g_web_buf[s] = buf` 写回，绝不跨语句持有 QHash 引用。同时 `wsSend` 增加 `state()==ConnectedState` 防护，避免写入已断开 socket。
- [x] 233. **验证**：修复后 3 轮 × 60 = 180 个并发请求，服务稳定存活、无崩溃日志；浏览器子代理真实加载 http://localhost:8090/ 确认四页界面渲染正常（非目录列表），截图已留存。
- [x] 234. **教训**：先前汇报"Web 已完成"未覆盖真实并发访问场景，导致用户看到的界面不可用。此类跨语句容器引用失效应通过 ASan + 高并发回归测试提前暴露。
